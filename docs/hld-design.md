# 重軽分解と方向付きパス集約の設計案

この文書は設計時の記録です。初期版は [重軽分解](../library/graph/heavy_light_decomposition.md) として実装し、実際の API と検証範囲はそちらを正とします。既存の [EulerTour](../library/graph/euler_tour.md) は維持します。重軽分解と順逆の集約の背景は [AtCoder の解説](https://info.atcoder.jp/entry/algorithm_lectures/heavy_light_decomposition) を参照します。第三者の実装コードを取り込むことを意味しません。

## 対象と構成

- 頂点 `0..n-1`、`n >= 1` の連結な単純無向木と、構築時に指定する固定根を対象とします。構築後の辺の追加・削除や根の変更は対象外です。`u` と `v` の位置関係を比較するときの親子・深さはこの根によります。
- 第一層は **HLD 本体**です。木の情報、頂点と配列位置の対応、LCA、部分木範囲、方向付きパスの区間分解を提供します。値やセグメント木は所有せず、利用者の適合する隣接リストを読み取ります。既存の `Graph<T>` でも使えるようにします。
- 第二層は **集約の補助**です。順逆の集約を持つモノイドと、頂点または辺の値をセグメント木に配置して使うための薄いラッパーを検討します。既存の `cp::Segtree<M>` と ACL を再利用し、HLD 自体には ACL 依存を持たせません。
- 区間更新は上の分解を既存の遅延セグメント木に接続して実現します。任意の演算に対する区間更新を自動生成しません。
- 木のコピーや外部隣接リストの破壊的な並べ替えは行わず、構築後は HLD 自身の配列のみを参照します。一直線の大木で再帰スタックに依存しないよう、構築は反復処理を前提にします。

## HLD 本体の契約

名前は仮案です。すべての配列範囲は `[l, r)` です。

| 操作 | 契約 |
| --- | --- |
| `index(v)`, `vertex(i)` | 頂点と HLD 順序の相互変換。親の位置は子より小さく、各重辺パスと各部分木は連続する |
| `parent(v)`, `depth(v)` | 固定根に対する親と深さ。根の親は `-1`、根の深さは `0` |
| `lca(u, v)` | 固定根に対する最小共通祖先 |
| `subtree_vertices(v)` | `v` 自身を含む部分木の頂点区間 `[index(v), index(v) + size(v))` |
| `subtree_edges(v)` | `v` とその親の辺を除く、部分木内の辺区間 `[index(v)+1, index(v)+size(v))` |
| `path_vertices(u, v)` | `u` から `v` の順に、両端と LCA を含む頂点列を表す方向付き区間列 |
| `path_edges(u, v)` | `u` から `v` の順に、通る辺だけを表す方向付き区間列。`u == v` なら空 |

区間要素は `{l, r, reversed}` とし、`l < r`、`false` は配列位置の昇順、`true` は降順で訪問します。区間自体も `u → v` の訪問順で返します。返却列を展開すると、頂点モードでは各頂点が1回、辺モードでは各辺の子側頂点が1回現れます。非可換演算の利用者が区間順序を推測する必要はありません。

辺モードでは親子間の辺を **子の位置**に格納します。異なる重パス間を上るときは、そのパス先頭の位置が表す親への軽辺も含みます。最後に同じ重パスへ入った区間では LCA の位置を除きます。根の位置には辺がないため、辺データ配列では単位元を入れ、パス・部分木の辺結果に含めません。`subtree_edges` が返すのは部分木の**内部の辺**だけです。

## 順序と辺の方向

モノイド `M` の `op(a,b)` は「訪問列 `a` の後に `b`」を結合すると定義します。関数合成などの実際の評価順は `M::op` の定義に従います。逆元は不要で、`op` の結合律と単位元が必要です。

各区間に `forward`（配列位置の昇順）と `backward`（降順）の集約を持たせ、隣接する左区間 `L` と右区間 `R` は次の順に結合します。

```text
combined.forward  = op(L.forward, R.forward)
combined.backward = op(R.backward, L.backward)
identity           = {e, e}
```

- 頂点値が方向によらない場合、葉は `{value, value}` です。順逆は値そのものではなく**頂点を結合する順序**の違いです。
- 辺の葉は `{親→子の値, 子→親の値}` です。値は互いに独立で、逆元である必要はありません。無向の重みなら両方を同じ値にします。
- `u → v` の各区間を順に処理し、`reversed == false` ならその区間の `forward`、`true` なら `backward` を、結果の**右側に** `op` で結合します。

例として、`0` を根とする `0—1—2` で辺の値が `0→1 = A`、`1→0 = a`、`1→2 = B`、`2→1 = b` の場合、文字列連結による辺パスの値は `0→2 = AB`、`2→0 = ba`、`1→1 = ""` です。辺の両方向の値と、結合順序の両方が変わります。

既存 `Graph<T>::add_edge` は両方向に同じ `cost` と辺 ID を登録します。非対称の値はグラフの `cost` に自動で含まれるものとせず、例えば `set_edge(u, v, uv, vu)` で明示的に渡す案です。`u,v` は実在する親子辺で、`uv` は `u→v`、`vu` は `v→u` の値です。どちらが親でも意味が変わらないように内部で並べ替えます。ID を使う初期化を加える場合も、入力時の端点順と値の向きを明示し、`idx` の存在や一意性を一般の隣接リストに要求しません。

## 更新と代数的な制約

点更新は、頂点値なら対応する葉、辺値なら子の位置にある両方向の葉を更新します。値を別々に更新する API の必要性は、利用例を見て判断します。

区間更新には作用の恒等性・合成・集約との両立が必要です。[ACL lazy_segtree の要件](https://atcoder.github.io/ac-library/production/document_ja/lazysegtree.html)に加え、順逆の両成分に適用した結果も、それぞれ元の葉を更新してから順逆に集約した結果と一致しなければなりません。単に `forward` と `backward` に同じ処理を適用すれば、任意の非可換操作に対応できるわけではありません。

辺の両方向で異なる更新を行う場合は、親→子と子→親のそれぞれにどの作用を適用するかを定義します。特に「`u → v` に沿う値だけを更新する」操作では、区間の `reversed` に応じて更新対象の成分が入れ替わります。この種の API と作用の条件は別途設計・検証し、初期版で未対応なら明示します。既存 `RangeAdd` / `RangeAssign` を任意の順逆状態にそのまま適用可能と仮定しません。

## 計算量と制約

- 構築・補助配列は `O(n)` 時間・メモリ。LCA とパスの区間分解は `O(log n)` 時間、返却する区間列は `O(log n)` 個を想定します。
- セグメント木の区間取得・更新が `O(log n)` なら、パス取得・更新は `O(log² n)`、部分木取得・更新は `O(log n)` です。順逆両集約には集約値を2つ保持する分のメモリが必要です。値のコピー・`op`・作用が定数時間でない場合はその費用も含めます。
- 可換な演算でも最初は順逆両対応 API を正しく使えるようにし、単一集約での省メモリ版は必要性とインターフェースを見て別途検討します。
- この案は EulerTour の API や計算量を保証しません。現在の EulerTour の `query_vert` は LCA を除く一方、この案の頂点パスは両端と LCA を含むため、移行時は明示的な違いに注意します。

## 検証計画

1. HLD の区間分解を、1頂点、鎖、星、根・LCA が端点の場合、別重パスをまたぐ場合、ランダムな木で素朴な `u → v` の頂点・辺列と比較します。すべての `u,v`、逆方向、部分木の範囲を検査します。
2. 文字列連結や一次関数合成で順序を比較します。辺の上向きと下向きに異なる値を与え、点更新後も全パスを比較します。辺パスの `u == v`、最大・最小の値、辺の入力端点の逆転、根の変更を別インスタンスで検査します。
3. 許可した遅延作用ごとに、結合律・単位元・写像と結合の両立・作用の合成順を確認し、配列と木の素朴モデルで更新後のパス・部分木を比較します。方向依存更新を提供する場合は `u → v` と `v → u`、重パス境界をまたぐ例を追加します。
4. 実装後に適合する場合、[Vertex Add Path Sum](https://judge.yosupo.jp/problem/vertex_add_path_sum)、[Vertex Set Path Composite](https://judge.yosupo.jp/problem/vertex_set_path_composite)、[Vertex Add Subtree Sum](https://judge.yosupo.jp/problem/vertex_add_subtree_sum) を judge-backed 検証候補にします。方向別の異なる辺値は問題がその仕様を直接扱うとは限らないため、独立した素朴比較も維持します。問題の存在は [Library Checker の一覧](https://judge.yosupo.jp/) で確認しています。

## 初期版の選択と今後の検討

- 初期版は区間列と、点更新・順序付き取得の非所有ラッパーを提供します。
- パス区間はコールバックでも順に受け取れ、分解のための動的確保を避けられます。非所有ラッパーには一時 HLD を渡せず、参照先の HLD とセグメント木の寿命は呼び出し側が管理します。
- 遅延更新は区間分解と利用者が定義する遅延セグメント木を組み合わせます。方向別の遅延作用を自動で扱う専用ラッパーは未提供です。
- EulerTour の LCA を除く頂点パスの互換補助は未提供です。必要なら明示的な操作として検討します。
