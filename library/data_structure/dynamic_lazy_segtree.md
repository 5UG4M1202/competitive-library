# 動的遅延セグメント木

広い整数座標の半開区間を対象に、区間作用・区間集約・境界探索を行います。必要になった節点だけを作るので、全座標に配列を確保できないときに向きます。座標が小さく固定されるなら、実装と所有権が単純な [ACL のセグメント木](monoid_segtree.md) を先に検討してください。

## 最小例：区間加算と区間和

```cpp
#include "library/data_structure/dynamic_lazy_segtree.hpp"
#include "library/data_structure/monoid_segtree.hpp"

using P = cp::RangeAdd<long long, cp::AggregateKind::sum>;
using Tree = dynamic_lazy_segtree<P::value_type, P::op, P::id,
    P::action_type, P::mapping, P::composition, P::action_id>;

Tree seg(0, 1000000000LL,
         [](long long l, long long r) -> P::value_type { return {0, r - l}; });
seg.apply(2, 5, 3);             // [2,5) の各値に 3 を加える
auto sum = seg.prod(0, 10).value; // 9
```

例の `P` は ACL を必要とする別ヘッダー由来です。動的木のヘッダー自身は標準ライブラリのみを使うため、ACL なしでも同じ関数シグネチャの値・作用を自分で定義できます。`cp::RangeAssign` や `cp::RangeAffineSum` も値域と演算の前提を満たせば使えます。`F` は `id()` と等値比較できる必要があります。

検証ページのコード欄で「提出用の利用例」を選ぶと、上の例に必要な両ヘッダーと `main()` をまとめてコピーできます。出力は `9` です。ACL の `#include` は残るため、提出環境に ACL が必要です。動的木だけを使う場合は `bundled` を選んでください。

## インターフェースと前提

- コンストラクタは座標範囲 `[L, R)` と、必要なら初期区間集約 `init(l, r)` を受け取ります。省略時は `e()` です。`L < R` かつ `R - L` が `long long` に収まることが必要です。空の木は構築できません。
- `init` は管理範囲内の任意の非空部分区間について、`init(l, r) == op(init(l, m), init(m, r))` を満たす実際の初期配列の集約を返してください。和を管理する場合、要素数を持つ型の初期集約は、値がゼロでも長さ `r-l` が必要です。
- `apply(l, r, f)` は `[l,r)` を更新し、`prod(l, r)` はその集約を返します。空区間の更新は何もせず、空区間の集約は `e()` です。`all_prod()` は管理範囲全体の集約です。
- `max_right(l, g)` / `min_left(r, g)` は単調な判定条件が成立する最長範囲の端を返します。`g(e()) == true` が必要です。両操作とも境界値 `l == R`、`r == L` を受け取れます。
- `op` の結合律・単位元、作用の恒等性・合成、作用と `op` の両立を満たしてください。`composition(f, g)` は先に `g`、後に `f` を適用する合成です。
- 個々の値、要素数、集約と作用の**すべての中間結果**が利用する型で表現できることが必要です。オーバーフローは検出しません。数値の番兵は木自体にはありません。`init` や演算が番兵を使う場合の制約はその定義に従います。

## 所有権と計算量

木が節点を所有し、破棄時に解放します。浅いコピーによるノード共有を避けるため、コピー構築・コピー代入は禁止し、移動構築・移動代入を提供します。移動元は破棄または別の木の移動代入先として扱ってください。互換性のため公開されている `root` や `Node::ch` は非所有ポインターです。外部から解放・書換えしないでください。木の破棄や移動代入で古いポインターは無効になります。

初期構築は `O(1)`、`U = R-L` として更新・集約・境界探索は `O(log U)`、各操作で新たに確保するノードは `O(log U)` です（`op`、作用、`init`、判定が定数時間の場合）。全体集約は `O(1)`、メモリはそれまでに確保したノード数に比例します。検索でも遅延伝播や境界探索でノードを作ることがあり、不要になった個別ノードの途中解放はしません。
